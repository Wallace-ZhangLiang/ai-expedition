# LLVM 是什么：编译器基础设施与 IR

> **定位**：学 Triton 源码到处撞见 LLVM、MLIR、IR 这些词（`lib/Dialect`、`lib/Conversion`、`-emit=llvmir`……），需要知道这到底是啥、和 Triton 什么关系。

## 〇、一句话

**LLVM 是一套开源的「编译器零件库」（编译器基础设施）**，核心发明是一个统一的**中间表示 IR**——让「任何语言」和「任何硬件」可以自由拼装。**Triton 就是用它家的 MLIR 搭起来的**。

## 一、它解决什么问题：N × M 组合爆炸

世界上有 N 种语言（C/C++/Rust/Swift……）、M 种硬件（x86/ARM/CUDA GPU/昇腾 NPU……），编译器要把语言翻译成硬件指令：

```
老式做法：一门语言 × 一种硬件 = 一个完整编译器
  → 要支持全部组合，得写 N × M 个编译器，谁也维护不动

LLVM 做法：语言方只管翻译到「中间语言」，硬件方只管翻译「中间语言」到机器码
  → N + M 个模块，自由组合
```

| 角色 | 只需要做 | 完全不用管 |
|---|---|---|
| 语言前端（Clang、Rust、Swift……） | 自己的语言 → LLVM IR | 硬件是啥 |
| 硬件后端（x86、ARM、CUDA……） | LLVM IR → 自己的机器码 | 语言是啥 |

> **比喻**：LLVM IR 像国际物流的中转仓——各国货物（语言）先入库统一打包，再发往各国目的地（硬件），不用每两个国家之间都开一条直航线。

## 二、三段式架构：前端 / 中端 / 后端

```
 源代码          LLVM IR              LLVM IR           机器码
┌──────┐  ┌────┐  ┌───┐   ┌─────┐   ┌───┐  ┌────┐  ┌────────┐
│ C++  │→│Clang│→│ IR │ → │ opt │ →  │ IR │→│llc │→│ x86/ARM│
└──────┘  └────┘  └───┘   └─────┘   └───┘  └────┘  └────────┘
  前端      生成     统一格式   中端优化    优化后   后端      目标硬件
(管语言)                      (通用优化)          (管硬件)
```

- **前端**：解析语法、类型检查，输出 IR（C/C++ 用 Clang）
- **中端**：在 IR 上做与硬件无关的优化（死代码消除、内联、循环优化……），工具叫 `opt`
- **后端**：指令选择、寄存器分配，生成具体硬件的机器码，工具叫 `llc`

每个阶段都是独立零件，可单独替换、单独复用——这就是「基础设施」的含义。

## 三、LLVM IR：整个体系的心脏

IR（Intermediate Representation，中间表示）是一门**设计给编译器用的低级语言**，长这样（一个人畜无害的加法函数）：

```llvm
define i32 @add(i32 %a, i32 %b) {
entry:
  %result = add i32 %a, %b
  ret i32 %result
}
```

三个特点，看到就不会懵：

| 特点 | 意思 |
|---|---|
| **类 RISC 指令** | 一行一个简单操作（add/ret/mul……），像汇编但更规整 |
| **强类型** | 每个值都标类型（`i32` = 32 位整数），不是汇编那种裸寄存器 |
| **SSA** | 每个变量只能赋值一次（`%result` 定义后不再变），要「改」就生成新名字（`%result1`、`%result2`…）。这让优化器分析起来极其省事 |

IR 有三种存在形态：编译器内存里的对象 / 文本 `.ll`（人读的）/ 二进制 `.bc` bitcode（机器存的）。

> **不用学会写 IR**，只需要建立「IR = 语言和硬件之间的中间语言/中转站」这个概念。Triton 调试时 dump 出来的东西，都是管线各阶段的 IR。

## 四、LLVM 家族成员（认脸即可）

| 名字 | 是啥 | 和我们的关系 |
|---|---|---|
| **LLVM 核心** | IR 定义 + 中端优化 + 几十种硬件后端 | 地基的地基 |
| **Clang** | C/C++ 前端 | 编译 C/C++ 的都会用到 |
| **MLIR** | **多层 IR 框架**：让你方便地定义自己的「方言」和多层 lowering | ⭐ **Triton 的直接地基** |
| `opt` / `llc` | 中端优化器 / 后端代码生成器（命令行工具） | 查资料会见到 |
| lld / libc++ | 链接器 / C++ 标准库 | 周边，知道存在即可 |

**MLIR 值得多记一句**：LLVM IR 只有一层（已经很底层），而 MLIR 允许**自定义多层 IR**——先在高层（贴近算法语义）优化，再一层层往下降。编译 GPU/NPU 这种「从算法到硬件距离很远」的场景特别需要它。

## 五、和 Triton / 后端的关系（重点）

Triton 的编译器部分就建在 MLIR 上：**用 MLIR 定义了自己的方言**——TTIR（Triton IR，块级语义）→ TritonGPU IR（加上硬件细节）→ 一路 lower 下去。仓库里那些目录就是干这个的：

- `lib/Dialect/` —— 定义 Triton 自己的 IR 方言（`tt.load`、`tt.dot` 这些指令的「语法」）
- `lib/Conversion/` —— 方言之间的层层转换（lowering）
- `lib/Target/` —— 最终落到目标硬件

两条后端路线的差别（以 NVIDIA 和昇腾为例）：

```
                Python kernel（@triton.jit）
                        ↓
              TTIR → TritonGPU IR        ← 前半段：MLIR，两边一样
                ↓                    ↓
      ┌─ NVIDIA 路线 ─┐      ┌─ 昇腾路线 ──────────┐
      │ LLVM IR → PTX │      │ AscendNPU-IR(毕昇系)  │
      │   → cubin     │      │   → 昇腾机器码         │
      └──────────────┘      └────────────────────┘
```

- **NVIDIA**：TritonGPU IR 降到 **LLVM IR**，再由 LLVM 的 NVPTX 后端生成 PTX（GPU 上的「汇编」）
- **昇腾**：后半段换成基于华为**毕昇编译器**（Bisheng，本身就是 LLVM 的一个分支）的 NPU 编译路线

> **一句话总结关系**：Triton 的「骨架」（IR 定义、多层 lowering 框架）来自 LLVM 的 MLIR；NVIDIA 后端直接用 LLVM IR 落地；昇腾后端把最后一段换成了自家的毕昇系编译器——但**追根溯源整个体系都是 LLVM 系的**。

## 六、学习路上会在哪撞见它

| 你会看到 | 它是啥 |
|---|---|
| 仓库 `lib/Dialect`、`lib/Conversion` 目录 | Triton 用 MLIR 定义的方言 + 层层转换的 pass |
| 报错/日志里的 `tt.load`、`ttg.*` | Triton 方言里的指令（TritonGPU IR） |
| 调试选项 dump 出的 `llvm ir` | 管线中段的标准 LLVM IR 文本 |
| `TRITON_BUILD_NPUIR=ON` | 源码安装时要现场编译 NPU IR 那套组件 |

> **该掌握的**：IR = 中间语言、三段式（前端/中端/后端）、MLIR = 多层 IR 框架、后端在哪一段换了实现。
> **不用掌握的**：手写 `.ll`、读 LLVM 源码。概念通了，看文档和报错不懵就够了。
