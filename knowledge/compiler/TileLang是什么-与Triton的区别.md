# TileLang 是什么：与 Triton 的区别

> **定位**：学习 Triton 途中遇到生态里另一个编译器 TileLang，需要知道它是什么、和 Triton 什么关系。

## 一、一句话先看懂

**Triton 和 TileLang 都是「用写代码代替手写底层算子」的编译器**，但定位不同：

- **Triton** = 行业标准、生态最大（PyTorch 官方、vLLM 都在用）
- **TileLang** = 新兴选手，主打「性能极致、接近手工调优」→ 学术背景强（MIT 团队）

## 二、它俩到底在解决什么问题（共同点）

GPU / 昇腾 NPU 上跑一个「新算子」，有三条路：

```
① 算子库有现成的  → 直接用（预制菜）
② 手写底层指令     → 太慢、太难，普通人不干
③ 写高级代码让编译器生成  → Triton / TileLang 干这个
```

```
你写的「高级算子代码」（不用管底层寄存器/缓存）
        ↓ 编译器
硬件能跑的指令（GPU / 昇腾 NPU）
```

**共同点**：都解决「算子库覆盖不到的新算子，手写又太慢，编译自动生成」。

## 三、核心区别（一张表）

| 维度 | Triton | TileLang |
|---|---|---|
| **出身** | 学术→工业（OpenAI 发起，PyTorch 官方采纳） | 学术（MIT，清华团队背景） |
| **生态** | **最大**：PyTorch/torch.compile/vLLM 原生支持 | 小，正在长 |
| **目标** | **通用**：覆盖各种 kernel，稳定优先 | **极致性能**：逼近手工调优，但适用面窄 |
| **写法** | tile 思维（`tl.program_id`/`tl.load`/`tl.dot`） | 类似 tile 思维，但更「算子库化」（关注 tiling 策略） |
| **性能上限** | 编译器自动调优，通常 80-90% | 精细 tiling 可达 95%+（在它支持的场景） |
| **昇腾支持** | 有 triton-ascend 等后端，生态适配较成熟 | 有类似项目，成熟度更低 |

## 四、打个比方

- **Triton 像 C 语言**：人人用、标准、生态最大、要靠它吃饭。
- **TileLang 像某些激进的性能库**：有人追求极致时用，但主流开发不依赖。

## 五、学习建议

- **主线不偏**：如果目标是生态适配 / 后端开发，专注 Triton。
- **可选拓展**：跑通 Triton 示例后，瞄一眼 TileLang 官方页知道长啥样即可，不用深学。
